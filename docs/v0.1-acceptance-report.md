## Scenario and commands

The headless project uses the normal `SimulationEngine` and deterministic event
queue. `MAX` means that no wall-clock pacing is applied; it does not skip,
reorder, or parallelize canonical events. Public horizons are 1, 10, 100, and
500 years. The acceptance run used seed 42, current rules, a 100-year target,
and a checkpoint at year 37:

```powershell
dotnet restore LittleAges.sln --locked-mode
dotnet build LittleAges.sln --configuration Release --no-restore
dotnet run --project src/LittleAges.Headless/LittleAges.Headless.csproj `
  --configuration Release --no-build -- acceptance `
  --seed 42 --years 100 --rules m8-rng1-balance1 `
  --checkpoint-year 37 --database artifacts/acceptance.db `
  --output artifacts
```

The same CLI exposes `run` and `benchmark` for the supported horizons. JSON and
Markdown outputs use invariant formatting and stable ordering. The report-level
deterministic hash includes reporting configuration; the engine fingerprints
below are the canonical comparison.

The server's controls are operational only and route through the host's single
reader: `POST /api/v1/control/pause`, `POST /api/v1/control/resume`, and
`POST /api/v1/control/speed` with a bounded positive speed. Status publishes
paused state and the current operational speed. A speed of zero is the startup
paused configuration; the browser controls use safe positive speeds and never
change rules, history, decisions, or canonical state.

## Compatibility and follow-up

M6 remains available for explicitly selected old snapshots and its locked
goldens are unchanged. Fresh worlds and the manual acceptance workflow resolve
to `m8-rng1-balance1`. M8's sampled shortage-recovery boundary changes only the
M8 history transition semantics; supply/demand, RNG, decisions, and gameplay
state remain deterministic. The manual workflow is
`.github/workflows/v01-acceptance.yml`: `workflow_dispatch` only, Windows, locked
restore, Release build, 180-minute job timeout, seed 42, 100 years, year-37
checkpoint, and JSON/Markdown artifact upload.

Before this successful pair, two long-horizon validator gaps (birth-household
provenance for adults that later move households and immutable parent-age
validation) and a mature-world SQLite reopen preflight sentinel were corrected.
Those fixes were validation/persistence compatibility corrections only; they did
not change canonical rules, event payloads, RNG, or the fingerprints reported
here.

Remaining follow-up is the manual target-Windows/browser checklist and any
future performance work justified by separately recorded benchmark timings.
